# 本轮局域网测试（更新于 2026-09-11）

中继在 Mac：192.168.8.239:18081。需要 Mac 保持运行、不休眠，双方处于 192.168.8.0/24 可互通网络。
云端 pet.narendra.cn 尚未部署，本轮使用局域网；公网预备方案见 deploy/BAOTA.md。

## Windows

1. 从 NAS 的 `OnlineDesktopPet/test-builds/20260910/windows` 将整个文件夹复制到 Windows 本地目录，避免执行文件占用共享盘。
2. 先退出旧版小鸡，再双击 `Start-ChickLink.cmd`。也可直接运行 pet-client.exe；cmd 会清除旧测试环境变量并自动打开配对页。
3. exe 旁的 chicklink-connection.json、relay-public.pem 必须保留。里面是 Windows 专属测试令牌，不要用于 Mac 或上传 GitHub。
4. mDNS 会搜索 LAN 中继；未发现时回退 ws://192.168.8.239:18081/ws。
5. Mac 或 Windows 任一端输入另一端的配对码，只需操作一次。
6. 测试双方拍拍、换肤、文字聊天、小鸡气泡、提示音、静音保存、右键与 DPI。

## 对方在线状态

聊天页和右键/托盘的伙伴标签显示在线、离线或未知。空闲时气泡提示状态变化，不覆盖正在展示的聊天消息。

1. 配对后确认两端显示对方在线。
2. 退出一端客户端，另一端应显示离线；重新启动退出的一端后应恢复在线，无需重新配对（中继没有重启时）。
3. 断开一端网络，中继约 15 秒未收到数据后通知另一端离线；断网一端显示状态未知，而不是误报对方离线。
4. 恢复网络后等待自动重连。此状态表示客户端连接状态，不代表使用者正在操作电脑，不采集正在使用的应用。

本次更新需要新版中继，旧版 v0.3.3 服务器包不包含断线通知。测试目录沿用 20260910，已更新为当前开发构建。

## 故障检查

PowerShell：`Test-NetConnection 192.168.8.239 -Port 18081`。
TCP 失败先检查 Mac 是否休眠、IP 是否变化、主机防火墙与 Wi-Fi 客户端隔离。
mDNS 使用 UDP 5353；阻止发现时直连回退仍可工作。
如果有 VPN/代理，请确认此私网段走局域网。
健康地址是 http://192.168.8.239:18081/healthz；返回 ok 不等于已经配对。
配置文件包含测试身份；换网络后需要更新 relay_url 和 mDNS 广播地址。

NAS 同步不包含服务器 RSA 私钥、完整令牌表或 Mac 身份。请勿将 Windows 身份复制给第三个客户端。
两个测试身份对应服务端 owner-a（Mac）、owner-b（Windows）；显示昵称可自行设置。
服务端仍是内存配对，重启后重新配对；聊天历史在各端本地保留。
这是一份开发测试构建，不是 GitHub v0.3.3 发布包的替换。
