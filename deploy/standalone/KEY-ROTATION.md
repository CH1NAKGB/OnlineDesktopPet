# 生产 RSA 身份轮换

当前已发布客户端内嵌生产 RSA 公钥。TLS 证书续签不改变这个公钥，也不能替代 RSA 私钥恢复。

服务端新代码支持两个私钥：`RELAY_RSA_PRIVATE_KEY_PATH` 为当前私钥，`RELAY_RSA_PREVIOUS_PRIVATE_KEY_PATH` 为过渡期旧私钥。后者不配置时仍只使用一把钥匙。服务端只接受能用其中一把私钥解开的握手；使用旧钥的连接会留下不含密钥内容的日志。

轮换顺序：

1. 先完成现有私钥的离线加密备份和隔离恢复演练。生成新的 RSA-3072 PKCS#8 私钥及对应公钥；新私钥只能存服务器和受控离线备份，绝不进入客户端安装包。
2. 在测试环境验证新旧客户端均能连接双钥中继。生产升级前确认新版中继不会意外启用账号数据库，保留旧二进制和配置以便回滚。
3. 在生产中继配置新私钥为主钥、旧私钥为过渡钥并上线；先用旧版客户端验证，再用预置新公钥的新版客户端验证。
4. 发布新版客户端，收集旧钥握手日志和实际设备更新情况。确认所有需要继续使用的设备已更新后，移除旧私钥配置并重启专用中继。将旧钥从在线服务器清除，保留受控离线恢复记录。

若旧私钥泄露，继续允许旧钥握手就仍允许冒充中继。必须立即移除旧钥并通过可信渠道重新分发客户端；无法保证未更新的旧客户端继续连接。若旧钥丢失且没有备份，旧客户端也无法仅凭当前协议自动信任新钥。

这个过渡能力尚未部署到生产，不能把源码支持当成已完成轮换。不要在生产直接覆盖现有 `relay-private.pem`。
